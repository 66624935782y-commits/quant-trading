# quant-trading

面向 Python 新手的币安量化交易学习项目。使用 Python 与 Streamlit 提供网页界面，pandas 处理行情，Plotly 展示 K 线，CCXT 读取币安公共行情。

**当前版本：第 2 阶段，公共行情分析与本地数据保存。** 平台保持 `PAPER`（模拟交易）模式，无需注册币安账户或提供交易所 API 密钥。

## 现在可以做什么

- 在“行情分析”查看明确标记的离线演示 K 线，或者手动获取币安公共 K 线。
- 选择现货或 USDT 本位永续合约行情，选择 BTC、ETH、SOL 对 USDT 的交易对，以及 `1m`、`5m`、`15m`、`1h`、`4h`、`1d` 周期。
- 使用 Plotly 查看 K 线和成交量，查看已收盘行情的最新收盘价、区间涨跌幅、最高价、最低价与数据条数。
- 获取公共行情或加载演示时自动保存原始数据、整理后的 CSV 和来源记录；在“数据记录”重新加载已保存的数据，也可下载 CSV。
- 在“模拟账户”使用 **10,000 USDT** 虚拟资金，以固定示例价格 **BTC/USDT = 50,000** 练习手动买卖。手续费为 **0.1%**，滑点为 **0.05%**，持仓受到 **25% 仓位上限**约束。
- 下载当前虚拟账户的 JSON 快照。

**行情分析与模拟账户目前分开运行。** 获取或切换行情不会自动成交，不会改变虚拟账户，也不会把模拟账户的固定练习价格换成市场价格。USDT 合约仅供行情分析；虚拟买卖仅支持现货练习。

当前版本还没有策略回测、收益曲线、最大回撤计算、自动模拟交易或持久化模拟账户。账户保存在 Streamlit 会话中，服务重启或开启新会话会重新开始；下载的 JSON 暂不支持导入恢复。详细使用方法见 [行情与数据保存指南](docs/market-data.md)。

## 安全边界

- 初始模式必须为 `PAPER`，当前版本仅支持这个模式。
- 真实下单、提现、转账及杠杆功能全部关闭，并使用独立安全开关防止误启。
- 公共行情客户端只访问公开 K 线，不访问账户、不提供交易所订单适配器，也不要求任何交易所密钥。
- USDT 本位合约只做行情分析，不启用杠杆、做空或合约交易。
- 密钥不得写入源码、配置示例、日志或提交到 Git。
- 凡涉及真实资金的后续需求，必须先停止并解释风险；本项目不会通过当前界面打开真实交易。

手续费和滑点是简化学习模型，不代表真实交易所的完整成交规则。演示 K 线为人工生成的数据；模拟结果不能保证实盘收益。

## Windows 从这里开始

下载 [quant-trading-windows.zip](https://github.com/66624935782y-commits/quant-trading/raw/refs/heads/main/downloads/quant-trading-windows.zip)，**完整解压**后双击 `setup_windows.cmd`，安装依赖、运行测试并启动页面。以后双击 `start_windows.cmd` 即可启动。已有 Python 时脚本会自动识别；缺少 WinGet 时按 [Windows 指南](docs/windows.md) 手动安装官方 Python。

从第一阶段升级时，先下载需要保留的 JSON 账户快照，再关闭原来的运行窗口。将新版 ZIP 解压到**新的文件夹**后运行安装脚本，不要覆盖正在运行的旧项目，也不要删除旧 `.venv` 或 `data`。第一次启动 Streamlit 如出现 `Email:` 提示，留空并按回车即可。

手动安装及诊断命令如下；请在包含 `app.py` 的项目目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m streamlit run app.py --browser.gatherUsageStats=false --server.address=127.0.0.1
```

启动后保持终端开启，在终端按 `Ctrl+C` 停止服务。首次安装需要网络；离线演示和本地已保存行情不依赖币安连接。获取公共行情是否成功取决于网络及交易所服务限制，失败时页面会展示错误，不会自动换成演示数据。

## 分阶段开发

每个阶段增加一组可验证功能，完成后运行相应测试。

| 阶段 | 实施内容 | 验收重点 |
| --- | --- | --- |
| 1：已完成 | PAPER 配置、虚拟现货账户、离线网页、基础测试 | 费用与资金计算正确；危险开关不能开启；模拟交易不调用真实订单接口 |
| 2：当前阶段 | 现货与 USDT 本位合约公开 K 线；pandas 校验；Plotly 展示；原始行情保存及重新加载 | 不需要密钥；正确处理时间与重复数据；移除未收盘及未来 K 线；网络失败可解释；保存文件经校验后能重新读取 |
| 3：下一阶段 | 简单策略、下一根 K 线成交、费用与滑点、资金管理、资金曲线与统计 | 防止未来数据泄漏；用已知样本核对收益和最大回撤；保存可复现的回测结果 |
| 4：待开发 | 持久化模拟账户与交易流水、中断恢复、重复操作保护 | 恢复后的余额和持仓一致；失败不产生半笔交易；仍不调用真实订单接口 |
| 5：待设计 | 交易所模拟盘与实盘适配器的边界、能力检查、安全开关 | 只形成设计与测试替身；真实资金功能保持关闭，不实现真实下单 |

详细分层与验收标准见 [项目架构](docs/architecture.md)。

第 1 阶段已在 Linux 云环境运行测试、检查依赖与网页启动；用户的 Windows 截图也确认当时 **49 项测试通过且网页打开**。第 2 阶段在 Linux 云环境 **173 项测试全部通过**，服务启动和健康检查通过，已验证离线 K 线、公开请求路径的测试替身、保存及重启加载、失败保持状态和 PAPER 安全限制。第一阶段的 Windows 验证不能代替新版在 Windows 上的验证。当前云环境对现货、合约的真实公共行情请求均受到代理 `403` 限制，**尚未验证真实行情连通性**；这与使用本地样本的自动化测试结果分开报告，也不代表你的 Windows 网络一定会失败。GitHub Actions 的实际状态请查看仓库的 Actions 页面。

## 文件说明

0.2.1 修复了中文 Windows 默认 GBK 编码导致的一项测试失败。所有测试文件读写均明确编码，正常模式和 GBK 模拟模式各有 173 项测试通过。GitHub Actions 增加 GBK 模拟检查；这种模拟验证不代替修复版在 Windows 实机运行。

| 路径 | 用途 |
| --- | --- |
| `app.py` | Streamlit 网页入口 |
| `quant_trading/config.py` | PAPER 模式与安全配置 |
| `quant_trading/paper.py` | 虚拟账户与成交计算 |
| `quant_trading/market_data.py` | 只读行情请求、演示数据与 K 线校验 |
| `quant_trading/storage.py` | 行情文件保存与完整性校验 |
| `tests/` | 自动化测试 |
| `requirements.lock` | 固定版本与文件哈希的依赖清单 |
| `data/` | 本机行情文件，自动生成，不提交到 Git |
| `docs/` | 架构、Windows 安装与行情使用指南 |

原始行情和整理后的数据保存在不同文件中，每次保存使用独立记录。`data/` 被 Git 忽略；Git 忽略并不等于备份，请另行保存重要数据。历史回测结果的保存会在第 3 阶段实现。

开发者可在项目根目录运行 `python scripts/build_windows_zip.py`，重新生成 `downloads/quant-trading-windows.zip` 和对应 SHA256 文件。压缩包只含项目源码、测试、文档及启动脚本，不含虚拟环境、行情、日志、密钥或下载目录本身。
