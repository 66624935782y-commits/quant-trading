# AI Quant Trader Private — 私人币安 USDT 合约助手

这是独立的第一阶段 MVP。后端为 Python + FastAPI + CCXT，数据库为 SQLite，界面为单个 HTML + 原生 JavaScript + Tailwind CDN。无需 Docker、Node、MySQL，也没有策略、AI 分析或回测。

**默认关闭真实交易。** 开启实盘后，下单、平仓和撤单会改变真实账户。10 USDT 资金很少，部分币种的最低名义价值可能超过默认 10 USDT 上限，因而无法下单；这是正常拦截，不是安装失败。杠杆可能导致迅速亏损或强平。程序不能保证成交、平仓成功、盈利或损失不超过设置值。

## Windows 从这里开始

1. 将 `ai-quant-trader-private-windows.zip` **完整解压**到独立文件夹，例如 `C:\AIQuantPrivate`，不要在压缩包里面运行，也不要覆盖旧项目。
2. 双击 `install.bat`。已有 Python 3.10+ 时会创建本项目独立的 `.venv`；没有 Python 时尝试通过 Windows 自带的 WinGet 安装官方 Python 3.12。若 WinGet 不可用，会打开 Python 官方下载页，请安装 **Python 3.12 64 位**，勾选 **Add Python to PATH**，再双击安装脚本。首次安装需要网络。
3. 安装完成会打开记事本编辑 `.env`。该文件就在项目目录中。修改以下三项，其他配置先保持默认：

   ```dotenv
   BINANCE_API_KEY=你自己的APIKey
   BINANCE_API_SECRET=你自己的APISecret
   ADMIN_PASSWORD=你自己设置的至少16位独立密码
   LIVE_TRADING=false
   ```

   示例中的中文必须替换为自己的内容，不要复制示例密码。复杂密码包含 `#`、空格时请用双引号包住整个值。保存文件为 UTF-8；文件名必须是 `.env`，不要保存成 `.env.txt`。脚本不会覆盖已存在的 `.env`。**不要把 .env、密钥、数据库、日志或包含账户信息的截图发送给别人或上传 Git。**
4. 双击 `start.bat`，浏览器会在 HTTP 就绪检查通过后自动打开 **http://127.0.0.1:8000**（同一台电脑上的 localhost）。只有一个管理员，输入 `.env` 中设置的密码即可登录，无需用户名。
5. 页面顶部应显示“演练模式”。先确认真实余额、持仓和行情能读取，再用演练操作检查各种错误提示。演练模式读取真实数据，不提供假余额或假行情。
6. 关闭浏览器不会停止服务。双击 `stop.bat` 停止本项目后台服务。**停止服务不会平仓、撤销挂单或停止币安上的订单。** 请先核对持仓。

Python 3.12 Linux 已运行自动化及服务验证；本交付未在 Windows 实机、你的泰国 IP 或真实币安账户上验证。Windows 防火墙无需开放公网或局域网端口；服务固定只绑定 `127.0.0.1:8000`。

## 在币安配置 API

在币安官方网站登录你自己的账号，通过 API 管理创建适用于个人合约账户的 API。币安界面、地区资格和权限条件可能变化，请以你的账户实际页面为准。

- 只保留读取账户和 **USDT 合约交易所需权限**，**绝对不要开启提现权限**，不需要现货交易或转账权限。
- 把你自己的泰国静态出口 IP 加入 API 白名单；不要填写本机内网 IP，也不要开放给任意 IP。
- 将 Key 和 Secret 仅填入本机 `.env`，不要发给我或任何人。代码与日志连密钥前几位也不输出。
- 本工具面向普通 USDT 本位永续账户，支持单向/双向持仓；不切换你的账户持仓模式。不支持统一账户、Portfolio Margin、多资产保证金或币本位合约的交易工作流。
- 不安装代理或 VPN，不包含代理配置。若 Windows 已设置系统代理，CCXT 底层连接可能受系统环境影响，请在自己的网络设置中检查。

**若你已有其他 USDT 持仓或挂单，务必先核对。** 持仓页会显示全部 USDT 永续持仓；“撤销全部”和“紧急停止”也会涉及白名单以外的 USDT 合约，不只 BTC/ETH/SOL。撤销全部会取消已有条件止盈止损保护。

## 演练与实盘的区别

`LIVE_TRADING=false` 时，下单、平仓和撤单只记录本地演练日志，不调用任何交易所交易写接口，也不改变币安杠杆和保证金模式。页面仍显示真实账户，所以演练不会让余额或真实持仓发生变化；演练不是撮合模拟器，不会伪造成交或手续费。

需要真实交易时：先停止服务，在 `.env` 中将 `LIVE_TRADING` 改为 `true`，保存后重新双击 `start.bat`。检查顶部明确显示“实盘已开启”，再核对表单。每次下单均需要点击“确认下单”并在确认框再次确认。程序不会自行下单。

实盘模式下，普通订单默认限价；杠杆默认 5x，可选 1–20x；保证金模式只允许逐仓。无持仓和挂单时，程序按本次明确选择设置逐仓及杠杆，然后发单。已有全仓、不同杠杆或单向模式的反向仓位时拒绝开仓，不擅自更改。账户模式和交易规则不满足时需在币安自行处理。

## 金额、保证金与风控

- 输入 **10 USDT 名义价值**，不是投入 10 USDT 保证金。5x 下基础保证金约 2 USDT，另需费用和价格缓冲。
- 程序读取真实交易规则，向下截断数量，检查数量精度、LOT_SIZE、MARKET_LOT_SIZE、最低名义价值、限价步长及可用保证金。不会为满足最低门槛自动放大金额。
- 默认单笔名义价值上限 `MAX_ORDER_NOTIONAL_USDT=10`。开仓市价单按发单前最新价估算，**不是交易所成交金额硬上限**；滑点和价格变化可能使实际成交金额超过估算。限价执行也不保证一定成交。
- 默认日亏损限制 `MAX_DAILY_LOSS_USDT=5`。按 **UTC 自然日**（泰国每天 07:00、中国每天 08:00）汇总已实现盈亏、手续费和资金费。达到或超过限制后，后端拒绝新的开仓请求，仍允许平仓及撤单。它不是止损单，不计算尚未实现的浮亏，不自动平仓，也不能阻止此前已挂出的委托继续成交。
- 查询完整收益或余额失败时，禁止开仓；不会把未知值当作零。
- 部分平仓输入持仓数量的百分比，默认 100%。单向模式用 `reduceOnly`；双向模式指定 `positionSide`，不反向开仓。极小数量可能无法满足交易所数量步长，需在币安自行处理残余仓位。
- “紧急停止”**先把禁止开仓状态保存到 SQLite**，再尝试撤销全部普通/条件挂单、逐一平仓，并再次查询仓位及挂单。网络、交易所错误、未确认订单锁或部分成交都可能使它无法完成；必须看返回的逐项结果。`complete=false` 不是全部成功，请立即在币安操作。演练模式只锁开仓，不会真正平仓或撤单。
- 紧急锁重启后仍存在，只有登录后主动点击“解除紧急停止锁”才解除；日亏损限制不会因此绕过。没有常驻自动交易任务，电脑关机或服务停止后不能管理风险。

## 超时、重复点击和未确认订单

每个交易请求有持久化的唯一客户端编号，发送前先保存到 SQLite。相同编号只能返回原结果。发单超时后会先按该编号查单，**不自动重试发单**。

若查单仍无法确认，状态保留为 `pending`，重启后继续禁止新的交易订单，包括可能重复的平仓。撤单和紧急停止锁仍可尝试。先在币安核对真实订单、成交和仓位，再点击“核对未确认订单”。不要通过刷新页面、改编号、删除数据库或重新解压来绕过锁。

如果币安持续返回“找不到”，程序不会擅自认定从未成交，也不会自动清除锁。请保留客户端编号和数据库，在币安确认实际账户状态后再进行人工排查；本 MVP 不提供一键强制清锁。紧急情况下直接到币安管理仓位。

## 交易记录、数据库和日志

- `runtime/trader.sqlite3`：一个 SQLite 文件，保存会话哈希、紧急锁、订单意图、实际订单快照及成交明细。不要手工编辑或删除来绕过风控。
- 发送的订单立即记录；已确认订单会自动尝试拉取近期成交，读取本地历史时刷新本机未结束订单状态。成交费率、手续费币种和已实现盈亏均从币安成交响应读取，不用猜测值填充。
- 点击“从币安同步成交”会同步普通订单及实际成交。首次回填最近 90 天的 BTC/ETH/SOL 及当前持仓合约；以后重叠一天增量同步并去重。首次可能耗时几分钟，界面会等待，不要反复点击。同步中断后已保存批次仍保留，重新同步可继续核对。
- 交易所对未成交取消订单、过期订单及成交有保留期限制，所以**不能保证补齐安装前的全部历史**。历史 Algo 委托元数据不回填，已执行的 Algo 实际成交按成交接口保存。指定范围之外的历史交易对需在币安导出账单。程序不删除已保存订单和成交，页面各显示最近 500 条。
- `runtime/trader.log`：脱敏应用审计日志，自动轮转；`runtime/server-output.log`：启动输出；`runtime/server.json`：本项目受管理进程编号。
- 备份前先停止服务，再复制整个 `runtime` 文件夹和 `.env` 到你自己的安全存储。恢复后再次核对币安账户；本地历史不是交易所余额来源。

## 网页显示“拒绝连接”时

1. 先确认 ZIP 已经下载到自己的 Windows 电脑，并右键“全部解压”。聊天中的文件预览和云端服务不会自动成为你电脑上的服务。
2. 在解压后的 `AIQuantTraderPrivate` 文件夹中先双击 `install.bat`，按提示设置 `.env` 的管理员密码，再双击 `start.bat`。不要只手动输入 localhost 地址。
3. 新版会在检查通过后自动打开网页，统一使用 **http://127.0.0.1:8000**。IPv4 地址可避免某些电脑的 localhost 解析或 IPv6 差异。
4. 仍失败时双击 `diagnose.bat`，保留窗口查看提示。它会检查 Python 依赖、`.env` 是否存在、端口和本项目进程状态，不连接币安，也不显示密钥。
5. 如需协助，发送窗口最后几行或 `runtime/diagnosis.txt` 摘要；**不要发送 .env、Key、Secret 或原始账户文件**。该诊断不需要开启实盘。

新版修复了旧 PID 被复用时可能误报“已运行”的路径，也修复 Windows 虚拟环境多层 Python 进程导致的“网页已运行却报超时”。启动会核对进程身份和每次随机生成的启动标识，不再要求包装器 PID 等于 HTTP 服务 PID。Windows 优先使用 pythonw 在后台运行，避免多弹出空白窗口。旧进程记录失效时只清理记录，不会终止其他程序。若助手进程存在但 HTTP 未就绪，会明确报失败并给出诊断。

若已经使用过旧版，请先从旧文件夹运行 `stop.bat`，再将新版解压到新的文件夹。保留旧 `.env` 和 `runtime`，如需迁移请在服务停止后安全复制到新目录；不要覆盖正在运行的程序。

旧版若提示“启动超时”，但诊断显示端口有监听，可保持下面的 Python 窗口开启，手动访问 http://127.0.0.1:8000。如果能打开，则是已确认的旧版启动检测误报，不需要改密码、密钥或打开实盘。需升级时，先从旧目录运行 stop.bat，确认旧服务停止后再操作，不要删除 .env 或 runtime。

## 币安账户认证失败：只读检查

`LIVE_TRADING=false` 仍能读取真实账户，不必为查看余额开启实盘。如果密钥曾出现在截图、聊天或公开文件中，请先在币安删除该 API 并重新创建，旧密钥不要继续使用。新密钥只在自己的 .env 中填写，不要发送给别人。

每次修改 .env 后都需要：**Ctrl+S 保存 → stop.bat → 等待确认停止 → start.bat → 登录后刷新账户**。关闭浏览器不会让后台重新加载配置。账户错误与前述旧版 Windows“启动超时”误报是两件独立的事。

本版本提供 **check_api.bat**：双击后只读取币安公开时间、合约余额、持仓及一条收益流水，不下单、撤单、平仓或改杠杆。它会在第一个失败阶段停止，不在报告中显示密钥、签名 URL、余额、持仓或收益数值。结果保存在 `runtime/api_diagnosis.txt`，可以仅发送这个诊断摘要。

- `-2015`：币安将“无效密钥 / 出口 IP 不在白名单 / 权限不符”合并在一个错误中，不能仅凭这个码认定具体原因。若币安响应提供请求 IP，报告会显示经过格式校验的 IP，供你与 API 白名单核对；不要为了排查取消 IP 限制。
- `-2014`：检查 API Key 是否填错行、漏字符或带入额外内容。
- `-1022`：签名被拒绝，核对 Key 与 Secret 是否属于同一组 API，是否填反或有额外空格，并检查密钥类型。
- `-1021`：Windows 时间与服务器窗口不符，请打开系统“自动设置时间”并“立即同步”，然后重新启动程序。
- `-4056/-4057`：检查 API 类型及 RSA 配置，不要将公钥当成 Secret。不要擅自修改签名算法以绕过认证。

诊断中的“密钥已填写”只表示字段非空，不代表密钥有效。若只读诊断通过但网页仍认证失败，优先核对是否重启了同一文件夹的服务、是否仍有旧服务进程。浏览器查到的出口 IP 不一定就是 Python 程序的出口，需核对自己的网络路由；本工具不自动安装或配置代理，也不连接外部 IP 查询网站。

读操作失败时不会改为假余额；只有在你本机完成上述只读请求后，才能确认你的真实账户连通性。不要发送完整 .env、原始 HTTP 错误或 API 管理页面截图。

## 常见问题

**窗口提示管理员密码不正确或配置无效**：用记事本打开 `.env`，设置至少 16 位且不是示例内容的密码，确认金额为正数，`LIVE_TRADING` 仅用 `true` 或 `false`，然后重启。

**账户认证失败**：检查密钥拼写、USDT 合约权限、实际静态出口 IP 白名单、账号地区资格；不要通过开提现权限解决。

**连接超时/地区限制**：确认自己的电脑可访问币安合约服务。泰国 IP 不保证所有账户与 API 都可用，币安限制以实际响应为准。不要盲目重复下单。

**最低名义价值错误**：这是币安实时规则。默认 10 USDT 可能不够，不要只因看到错误就增加资金或杠杆。提高杠杆不能降低最小名义价值。

**端口 8000 被占用**：先用本项目 `stop.bat`；它只停止记录且身份匹配的助手进程，不会杀掉其他 Python 程序。其他应用占用时，请先自行关闭对应应用。不要改为对公网监听。

**页面样式加载不完整**：Tailwind 从 CDN 加载，需访问 `cdn.tailwindcss.com`；内置基础样式不依赖 CDN，表单与 API 功能仍可使用。

**服务停止后仓位还在**：正常。币安上的仓位和挂单独立于本机服务。请在币安自行处理。

requirements-dev.txt               可选测试依赖
manage.py                          初始化、进程管理及自动打开浏览器

trader/config.py                   .env 配置校验
trader/api.py                      认证、Cookie、同源保护、中文 API
trader/exchange.py                 CCXT 真实币安数据适配
trader/service.py                  订单、幂等、风控与紧急停止
trader/db.py                       SQLite 持久化
web/index.html                     唯一前端文件

```text

```
