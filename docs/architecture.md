# 项目架构与实施计划

本项目从离线虚拟账户开始，逐步加入公共行情、回测和持久化模拟交易。先验证账户安全与计算，再扩大功能；每个阶段都有可重复的自动化测试。

## 当前实现：第 1 阶段

```text
Streamlit 界面（app.py）
    │ 用户点击模拟买入 / 模拟卖出
    ▼
安全配置（quant_trading/config.py）
    │ 只允许 PAPER，危险能力开关关闭
    ▼
虚拟账户（quant_trading/paper.py）
    │ 校验资金、数量和仓位 → 计算滑点与费用 → 更新虚拟状态
    ▼
Streamlit 会话中的余额、持仓和交易记录
    └── 下载 JSON 快照
```

虚拟账户模块不依赖 Streamlit，也不依赖 CCXT 或币安 API。界面负责收集输入和展示结果；账户模块负责校验与计算，这样可以直接运行自动化测试。

这一阶段使用固定示例价格：`BTC/USDT = 50,000`，初始虚拟资金为 `10,000 USDT`。手续费率为 `0.1%`，滑点率为 `0.05%`，虚拟 BTC 持仓上限为 `25%`。它只支持虚拟现货买卖，不借贷、不做空、不提供杠杆。

仓位比例以成交后、扣除手续费和滑点影响后的账户权益为分母，按演示价格估值。金额计算使用 Decimal；输入绝对值不超过 `1e12`、最多 12 位小数，计算在独立的 80 位精度上下文中执行，拒绝无法精确表示的计算。本规则是学习模型，不代表币安交易对的实际精度与最小成交额规则。

账户暂时放在 Streamlit 会话中，服务重启或新会话会重新开始。JSON 下载是当前账户快照，尚不能导入恢复。此阶段不读取真实行情、不运行历史回测，也不把内存账户当作可持续运行的交易系统。

## 后续分层

| 层 | 责任 | 明确边界 |
| --- | --- | --- |
| 界面 | 输入参数、展示 K 线、账户、交易流水和资金曲线 | 不直接计算成交，不保存密钥，不调用真实下单 |
| 公共行情 | 获取现货及 USDT 本位合约公开 OHLCV 数据 | 只允许读取公开行情，不持有交易能力 |
| 数据处理 | pandas 时间索引、排序、去重、完整性检查 | 不伪造缺失价格；向用户说明缺口与异常 |
| 策略 | 根据当时已知数据产生买卖意图 | 不读取未来 K 线，不自行下单 |
| 回测引擎 | 推进时间、成交、费用、仓位管理和估值 | 默认在下一根 K 线执行，遵守可用资金限制 |
| PAPER 执行 | 用虚拟资金处理订单意图 | 不创建交易所订单，不使用交易所密钥 |
| 存储 | 保存原始行情、运行参数、流水及统计结果 | 保留来源与版本，防止覆盖原始数据和混淆多次运行 |
| 未来适配器 | 定义模拟盘与实盘的能力、权限及接口 | 独立安全开关，当前只设计接口与测试替身 |

第一版不会为这些规划层创建空代码文件；到对应阶段再实现并测试。

## 数据与结果保存

第 2 阶段开始，将原始行情保存在本地 `data/` 目录，并记录市场类型、交易对、周期、时间范围、获取时间、来源和数据校验值。现货与 USDT 本位合约应分别存储，避免同名交易对的数据混用。原始文件应保留，清洗后的数据单独输出。

第 3 阶段每次回测使用独立运行标识，保存输入数据标识、策略参数、手续费、滑点、初始资金、仓位限制、交易记录、资金曲线与统计摘要。相同输入应能复现相同结果。

`data/` 不进入 Git。使用者需要另外备份有价值的行情与回测结果；删除工作目录或重建环境会影响本地文件。第 4 阶段再实现账户持久化、恢复和完整性检查。

## 回测约定

1. 策略只读取当前及更早的数据；当前 K 线收盘后产生的信号，最早在下一根 K 线执行。
2. 均线等指标只用过去的数据计算，指标预热区间不能产生有效交易信号。
3. 成交价格纳入滑点，买入与卖出都计手续费；手续费、滑点和仓位参数必须随结果保存。
4. 买入不得让现金为负，卖出不得超过持仓；第一版只做现货多头交易。
5. 按统一估值时点计算账户总资产；累计收益率与最大回撤基于完整资金曲线计算。
6. 策略调参数据与最终评估数据分开，避免反复选择表现最好的参数后误认其为可靠预测。

OHLCV 是开盘价、最高价、最低价、收盘价和成交量的缩写。基于 K 线的回测无法还原每笔真实成交，因此必须清楚展示成交假设。

## 分阶段验收

| 阶段 | 应完成的验证 |
| --- | --- |
| 1 | 默认与唯一可用模式为 PAPER；危险开关拒绝开启；有效买卖的余额、费用和持仓正确；无效数量、资金不足、超仓位和超持仓卖出被拒绝；失败不改变账户；测试证明 PAPER 不会调用真实订单接口；网页可启动 |
| 2 | 用保存的测试数据检查时间、去重与完整性；验证公共行情客户端只读；真实公开行情请求成功或明确解释网络限制；图表可渲染；保存后可重新读取 |
| 3 | 用小型已知数据手算对照成交、费用、收益和最大回撤；未来数据改变不影响之前的信号；最后一根 K 线信号不越界成交；保存结果可重现 |
| 4 | 保存再加载的账户一致；重复操作不重复扣款；写入失败或中断后能恢复一致状态；交易历史可追溯；继续验证无真实订单调用 |
| 5 | 使用测试替身检查接口和安全开关；模拟盘与实盘能力明确隔离；不引入真实订单、提现、杠杆或转账实现 |

实时网络请求只用于行情读取的集成验证，常规自动化测试使用本地固定数据，避免因网络变化而产生随机失败。

## 安全设计

当前版本不需要任何交易所密钥。真实交易、提现、转账、杠杆的开关分别保持关闭；PAPER 账户不接受交易所客户端作为执行依赖。

后续即使增加 CCXT 公共行情客户端，也必须保持读取行情与执行订单分离。可调用 `fetch_ohlcv` 等只读方法的对象，不能传入 PAPER 成交路径。未来讨论实盘前，必须先停止实施并向用户解释资金风险，不能把模式切换做成能立即启动真实交易的普通按钮。

密钥不得提交到 Git、写入源码、展示在界面或输出到日志。若未来某项能力确实需要凭证，应单独设计安全注入方式；本阶段不添加密钥输入框。
