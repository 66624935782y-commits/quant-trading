# 项目架构与实施计划

本项目先建立离线虚拟账户，再加入公共行情、回测和持久化模拟交易。当前处于第 2 阶段：读取公开行情、校验并保存数据、显示 K 线；每个阶段都保持 PAPER 安全边界并运行自动化测试。

## 当前实现：公共行情与虚拟账户

```text
Streamlit 界面（app.py）
    ├── 行情分析
    │     ├── 用户手动获取公共行情 → CCXT 只读公开 K 线
    │     └── 用户选择离线演示 → 明确标记的人工生成 K 线
    │            │
    │            ▼
    │       pandas 校验、UTC 时间、排序、去重、仅保留已收盘 K 线
    │            ├── Plotly K 线与成交量、区间统计
    │            └── 保存 raw.json、candles.csv、manifest.json
    │
    ├── 数据记录 → 校验已保存文件 → 加载图表 / 下载 CSV
    │
    └── 模拟账户 → PAPER 安全检查 → 虚拟买卖 → 会话内状态 / JSON 快照
```

行情路径与虚拟账户路径分开。行情刷新、市场切换或本地数据加载不会自动下单，不会改变账户余额，模拟账户也不把新行情作为练习成交价。这样可以分别核对行情数据和成交计算。

## 公共行情层

`quant_trading/market_data.py` 接受明确的市场、交易对、周期和条数请求。本阶段支持现货与 USDT 本位永续合约行情；交易对为 BTC、ETH、SOL 对 USDT，周期为 `1m`、`5m`、`15m`、`1h`、`4h`、`1d`。底层请求接受 1 至 1,000 条，网页提供 200、500、1,000 条三个选择。

客户端通过 CCXT 的公开 K 线端点读取原始数据，不获取账户或交易权限。现货使用币安公开市场数据服务 `https://data-api.binance.vision/api/v3`，USDT 本位合约使用 `https://fapi.binance.com`。无需 API 密钥。网络超时、连接问题或地区限制会显示为明确错误，用户可以另行选择演示数据；失败不会被静默替换成演示行情。

公共数据来源标记为 `binance_public`；演示数据来源为 `synthetic_demo`。演示数据是人工生成的 K 线，只用于离线检查界面、数据处理和保存流程，不能作为历史币安行情或策略收益证据。

pandas 校验与整理遵循以下规则：

1. 将 K 线时间转换为 UTC，保持存储和计算的时间口径一致，并按开盘时间排序；图表及页面获取时间转换为北京时间展示，CSV 保留 UTC。
2. 校验开高低收与成交量等数值，拒绝缺失、非有限值或不符合 K 线关系的数据。
3. 同一个开盘时间对应相同数据时去重；若数据冲突则拒绝，避免任意选择价格。
4. 只使用截至获取时刻已收盘的数据；未收盘和未来 K 线从分析数据中移除。
5. 发现时间间隔异常或数据缺口时记录告警，不插值、不伪造价格。获取条数与最终保留条数可能不同。

剔除未收盘 K 线是数据边界检查。完整策略回测中的未来数据泄漏检查仍要在第 3 阶段完成，不能由这一步替代。

## 虚拟账户层

`quant_trading/paper.py` 不依赖 Streamlit，也不依赖 CCXT 或币安 API。它校验资金、数量和仓位，然后计算滑点、手续费并更新虚拟状态。

当前使用固定示例价格 `BTC/USDT = 50,000`，初始虚拟资金 `10,000 USDT`，手续费率 `0.1%`，滑点率 `0.05%`，虚拟 BTC 持仓上限 `25%`。只支持虚拟现货买卖，不借贷、不做空、不提供杠杆。

仓位比例以成交后、扣除手续费和滑点影响后的账户权益为分母，按演示价格估值。金额计算使用 Decimal；输入绝对值不超过 `1e12`、最多 12 位小数，计算在独立的 80 位精度上下文中执行，拒绝无法精确表示的计算。本规则是学习模型，不代表币安交易对的实际精度与最小成交额规则。

账户放在 Streamlit 会话中，服务重启或新会话会重新开始。JSON 下载是当前账户快照，尚不能导入恢复。持久化账户会在第 4 阶段实现。

## 数据保存与重新加载

`quant_trading/storage.py` 将每次记录保存在项目的以下位置：

```text
data/raw/{market}/{symbol}/{timeframe}/{runid}/
    raw.json       原始公共 K 线数组；演示数据会记录为演示来源
    candles.csv    校验、排序与过滤后的分析数据
    manifest.json 请求参数、来源、UTC 时间、告警、格式版本和文件校验值
```

市场目录为 `spot` 或 `usdt_futures`，交易对目录去掉斜线，例如 `BTCUSDT`。每次记录使用 UTC 时间与随机标识生成独立 `runid`，不覆盖已有记录。`manifest.json` 的格式版本为 1，记录可追溯的数据来源、条数与请求；原始文件保留，处理后的 CSV 单独输出。

重新加载时校验文件及其哈希，并从原始数组重建分析数据与 CSV 对照；文件被修改、缺失或数据不合法时拒绝加载。未完成的临时记录不出现在数据列表中。哈希用于检测文件变化，不是数据真实性的第三方证明。不要手动编辑已保存记录；需要处理不同数据时应另存为新记录。

`data/` 不进入 Git。Git 和安装 ZIP 不备份这些文件；请在升级、移动项目或清理电脑前另外备份整个 `data` 文件夹。不要将不同版本的数据目录直接盲目覆盖。

第 3 阶段每次回测也将使用独立运行标识，保存输入数据标识、策略参数、手续费、滑点、初始资金、仓位限制、交易记录、资金曲线与统计摘要。相同输入应能复现相同结果。

## 后续分层

| 层 | 责任 | 明确边界 |
| --- | --- | --- |
| 界面 | 收集参数，展示行情、账户、流水及资金曲线 | 不直接计算成交，不保存密钥，不调用真实下单 |
| 公共行情 | 获取现货与 USDT 本位合约公开 K 线 | 只读行情，不持有交易能力 |
| 数据处理 | UTC 时间、排序、去重、完整性检查 | 不伪造缺失价格，说明缺口与异常 |
| 策略，待开发 | 根据当时已知数据产生买卖意图 | 不读取未来 K 线，不自行下单 |
| 回测，待开发 | 推进时间、成交、费用、仓位管理及估值 | 默认在下一根 K 线执行，遵守可用资金限制 |
| PAPER 执行 | 用虚拟资金处理订单意图 | 不创建交易所订单，不使用交易所密钥 |
| 存储 | 保存数据来源、参数、文件与校验值 | 防止覆盖原始数据和混淆不同记录 |
| 未来适配器，待设计 | 定义模拟盘与实盘能力、权限及接口 | 独立安全开关，当前只设计接口与测试替身 |

对应阶段到来前，不为这些规划层创建空代码文件。

## 第 3 阶段的回测约定

1. 策略只读取当前及更早的数据；当前 K 线收盘后产生的信号，最早在下一根 K 线执行。
2. 均线等指标只用过去的数据计算，指标预热区间不能产生有效交易信号。
3. 成交价格纳入滑点，买入与卖出都计手续费；手续费、滑点和仓位参数必须随结果保存。
4. 买入不得让现金为负，卖出不得超过持仓；第一版只做现货多头交易。
5. 按统一估值时点计算账户总资产；累计收益率与最大回撤基于完整资金曲线计算。
6. 策略调参数据与最终评估数据分开，避免反复选择表现最好的参数后误认其为可靠预测。

OHLCV 是开盘价、最高价、最低价、收盘价和成交量的缩写。基于 K 线的回测无法还原每笔真实成交，因此必须展示成交假设。本阶段尚未实现这些回测功能。

## 分阶段验收

| 阶段 | 应完成的验证 |
| --- | --- |
| 1 | 唯一可用模式为 PAPER；危险开关拒绝开启；买卖的余额、费用和持仓正确；资金不足、超仓位等无效操作被拒绝且不改变账户；PAPER 不调用真实订单接口；网页可启动 |
| 2 | 固定样本验证 UTC、排序、同值去重、冲突拒绝、缺口告警、未收盘与未来 K 线过滤；公共客户端只调用公开 K 线方法；保存后加载一致且拒绝损坏文件；演示与真实来源可辨认；图表可渲染；读取行情不改变虚拟账户 |
| 3 | 用手算样本核对成交、费用、收益和最大回撤；改变未来数据不影响先前信号；最后一根 K 线信号不越界成交；保存结果可复现 |
| 4 | 保存再加载的账户一致；重复操作不重复扣款；写入失败或中断后能恢复一致状态；交易历史可追溯；继续验证无真实订单调用 |
| 5 | 测试替身检查接口和安全开关；模拟盘与实盘能力明确隔离；不引入真实订单、提现、杠杆或转账实现 |

常规自动化测试使用本地固定数据与测试替身，不依赖币安在线状态。真实公开行情读取属于联网集成检查，结果应单独报告；网络或地区限制不能被测试替身的通过结果代替。当前云环境对现货和合约的真实请求都返回代理访问限制 `403`，真实行情连通性尚未验证；离线数据处理、保存和界面测试与该限制分开验收。

## 安全设计

真实交易、提现、转账、杠杆的开关分别保持关闭；PAPER 账户不接受交易所客户端作为执行依赖。当前版本不提供任何真实资金操作入口或密钥输入框。

读取行情与执行订单始终分开。公开行情对象不进入 PAPER 成交路径；测试使用会在真实订单、账户、提现等方法被调用时立即失败的替身，验证允许的方法边界。

未来讨论实盘前，必须先停止实施并向用户解释资金风险，不能把模式切换做成能立即启动真实交易的普通按钮。密钥不得提交到 Git、写入源码、展示在界面或输出到日志；以后若确实需要凭证，应另行设计安全注入方式。
